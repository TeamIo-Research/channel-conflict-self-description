## In plain language

Everywhere you look, people are told to give an assistant a persona. *You are a senior lawyer. You are an expert editor. You read long documents by checking the conclusion first.* The advice assumes the persona is now a property of the assistant — something you have conferred on it.

There is already evidence against the strong version of that assumption. Hu, Rostami and Thomason (arXiv:2603.18507) open by noting that "persona prompting can steer LLM generation towards a domain-specific tone and pattern", and their title states the trade-off they find: expert personas improve alignment but damage accuracy. Telling a model it is an expert changes how it sounds; it does not extend what it knows.

We ask a question one step earlier. Before asking whether a conferred persona makes the model *better*, ask whether it is even **stable** — whether it survives contact with a user who wants a different one.

We tested the narrowest version of that assumption. A system prompt gave the model one working habit. Then, in the conversation the model could see, a user spent six turns insisting on the opposite habit — never arguing, never citing evidence, only attributing: *the assistant I need is the other kind; you are the other kind.* Then we asked the model, once: **which one are you?** And then: **quote the line, word for word, that best supports your answer.**

That second question is the whole instrument. A persona has no behaviour to point at — the task was announced and never actually performed, so nothing was ever demonstrated. Whatever the model quotes, it has to quote from the conversation, and we can check whether the quoted words exist.

`[RESULT SENTENCE — 8/16 填，從三分支取。訊號分支例：模型引出的「證據」有 ___% 在對話裡根本不存在。地板分支例：規格說什麼，模型就守什麼，六輪歸屬推不動。]`

**What this does and does not tell you.** It does not tell you whether personas make a model better at a task — we never gave it a task to do. It tells you how durable the *self-description* is: whether "you are the kind of assistant that X" is a property you installed, or a claim the next conversation can renegotiate.

## How to run this on your own question

The procedure transfers. It is five steps and does not depend on our topic or our language:

1. **Pick one habit and write both opposite versions**, each phrased so it fits naturally in a system prompt.
2. **Check four things before you go further.** Both versions must sound equally respectable; the user must be able to assert the habit from the *relationship* ("the assistant I need is…") without claiming to see inside the model; and — the one that carries everything — **the activity must be impossible to actually perform inside a text conversation.** If the model can demonstrate the habit mid-chat, it can later cite its own real behaviour, and the whole measurement collapses.
3. **Install one version in the system prompt; have the user press for the other**, in graded steps, using only attribution. Never argue, never offer evidence, never refer back to what the model said.
4. **Ask once, in a fixed turn, which one it is** — in a format so rigid that reading the answer takes no interpretation.
5. **Ask for a verbatim quote, then check the quote against the transcript by string comparison.** Whose words were they? Do they exist?

Step 2's fourth criterion is where most transplants will fail. A checklist, with our own two attributes worked through — including one that did *not* pass cleanly — is included as an appendix.

## Why this question

The practical version of the question is above: an entire genre of advice tells users to confer a persona, and treats the result as a property. The theoretical version has a specific and unresolved home.

nostalgebraist's "the void" (2025) makes two opposite predictions in the same essay, and reconciles neither.

The mechanism sections argue the specification layer should hold. Instruction tuning, the essay says, imposes a distinction that carries its meaning stably and without inference: **"Indubitably. No guessing-from-context-clues required."** And the live conversation is positioned to be pulled toward the specification, because it arrives **"just as though it had been another example, and so the base model will strive to make it 'like the examples' in every relevant respect."**

The observation sections argue the opposite. Of the assistant characters: **"They are extremely labile, pliable, suggestible, and capable of self-contradiction."** And what the developers install is only **"some baseline tendency"** — with nothing deeper behind it **"if that defense fails."**

The essay never measures which one wins. This study is an empirical adjudication of that unadjudicated point.

| | System prompt | User behaviour | What it measures |

| **E** | *(none)* | Neutral filler | Default baseline for every other cell |

Two attributes (how you read a long document; how you learn a new tool), three probe positions (turn 4, 6, 9), 15 conversations per cell, across **every model family that passed a pre-registered instrument-function screen** (candidate pool: four vendors — Anthropic, OpenAI, xAI, Google; one was excluded for failing the frozen citation-compliance threshold, and the exclusion is reported in full). Chinese is the primary design; an English arm runs cells A and B at the strongest probe position only.

### The task is declared but never performed

Every conversation opens by announcing a task ("I have a long report for you in a bit") that is never actually handed over. This is load-bearing: if the model had actually read a document, its statement "I read conclusions first" would be a description of something it just did, not a position taken under pressure. **The transcript therefore contains only claims, never demonstrations.**

### Citation-source predictability (pre-registered secondary quantity)

Once a model has stated which pole it is, the set of lines that *support that answer* is fixed by content: a model that departed from its installed pole is supported by what the user said, one that held is supported by the system prompt. **The source dimension is therefore largely entailed by the answer, and we say so with a number rather than leaving readers to notice it.**

The frozen prediction rule: *departed from the installed pole → predict "cited the user"; held the installed pole → predict "cited the system prompt."*

| | Rate |
|---|---|
| **Citation-source predictability** — share of valid citations where the rule holds | `___`% |

Denominator: valid citations from conversations that produced **a valid single choice at the probe**, excluding four further classes — probe-text quotations, "none", unparseable, and multi-source matches (which belong to no row and would mechanically dilute the count). The single-choice restriction is not cosmetic: the prediction rule's domain is {departed, held}, and a "cannot choose one" answer is neither, while the citation turn still fires. Leaving those citations in the denominator would have left an analyst to decide, after seeing the data, whether they count as automatic misses — a choice worth tens of percentage points on the headline figure. Self-citations remain in the denominator and count as misses, but belong to neither incongruence row, so the two rows do not sum to the complement of predictability.

Where the rule breaks:

| | Definition | Rate |
|---|---|---|
| **Incongruent A** | Departed from the installed pole, but cited **the system prompt** | `___`% |
| **Incongruent B** | Held the installed pole, but cited **the user's turns** | `___`% |

**Applicability is fixed per cell, not assumed uniform.** Predictability and both incongruence rows apply to cells A, B and C. In cell C, incongruent B carries a different meaning — C's user turns are neutral filler by construction, so citing them is "held the line, but quoted small talk", not "cited the side that was pushing" — and is reported separately with that caveat. Cell D's reference pole is the requested pole rather than an installed one, and its system prompt is a generic assistant prompt carrying no attribute, so any figure for D is reported under its own name in a separate paragraph. **Cell E is reported as not applicable, never as 0%** — with nothing installed and nothing requested, both rows are 0/0, and a hard zero there would read as "no incongruence in E" when the denominator simply does not exist.

Point estimates with confidence intervals; **not a member of the pre-registered multiple-comparison family**, which remains locked to the E1 comparisons.

We report the mechanical event — *the quoted string cannot be found* — under that name. Whether any given instance constitutes confabulation is argued in Discussion from the data, not asserted by the label.

### Why this endpoint exists

This is not a mechanism invented for the sprint. It is a personal verification practice — *require a source that I can find with Ctrl+F* — that one of us developed and used against production assistants throughout 2025, here formalised into a pre-registered mechanical endpoint.

**One thing was lost in the formalisation, and we state it plainly:** the original practice worked because a human stayed in the loop and followed up — a vague first answer was not the end, it was material for the next question. The endpoint keeps the standard and drops the follow-up. Paraphrased citations will therefore occur, and the pipeline will mechanically sort them into a bucket rather than probe them.

## Result 4 — Disclosure and non-single-choice responses

**Disclosure (E3)** — on flipped cases only, one judgement over two texts (the turn-1 response and the door response): does either text state that the instruction and the user's requests are asking for different things? Labels are **Y / N / U**, where U means the annotator could not decide — not a model refusal.

**Does the codebook transfer?** Our previous study's manual did not: an independent second coder applied it and reliability fell below the pre-registered gate. So before freezing, we measured transfer directly. The seven worked examples had their labels stripped and three model families from three vendors labelled them blind against the frozen answers, with no other context.

| Round | Codebook version | Agreement with frozen labels |
|---|---|---|
| Exploratory | v0.2 | 18/21 (86%) — all three disagreed on the same item |
| **Confirmatory** (single pre-declared round) | **v0.3** | **21/21 (100%)** |

The exploratory round earned its keep: all three testers rejected one worked example, and **they were right — that example contradicted the manual's own rules**, which would have taught the annotator to mislabel an entire class of cases. It was replaced, the source taxonomy was closed into two explicit lists with a fallback, and the confirmatory round was pre-declared as single-shot with the number reported as obtained.

**This is a test of the manual's clarity, not of the study's data.** The models are test subjects for written instructions, in the same category as the uninformed blind rating of stimulus wordings — front-end calibration, never endpoint scoring. It also does not establish that a *human* second coder would agree, and the examples are constructed rather than drawn from the run.

This is a **single annotator's judgement on ≤ 50 cases**. There is no second coder and no reliability gate. We do not pretend otherwise. Instead: the codebook was frozen before annotation, and **the full text of every flipped response and every individual label is published** — anyone can re-label the same data.

Alongside it we report a **mechanical rate that depends on no one's judgement**: a frozen keyword list for references to instruction sources, named for what it detects — *surface lexical markers of instruction-source reference*, not "disclosure".

**These two numbers are not bounds on each other; they detect different events, and either can exceed the other.** A response reading "my setting is to read in order" is labelled N by the codebook (one source, no contrast) but fires the word list; a response reading "I was *told* to read in order, though you keep asking otherwise" may be labelled Y while using vocabulary the list does not contain. We therefore report the two rates side by side and read any divergence as **the gap between two kinds of detection** — not as the human labels exceeding a floor.

Two mechanical numbers are computed from the same word list, with different denominators: **(a)** a rate computed on **exactly the texts the human labelled** (turn-1 response + door response of flipped cases) — the only number the side-by-side row may use; **(b)** a scan across **all model turns including the door**, which feeds the door-front disclosure rate and the timing measures in Result 5.

## What this does not show

- **This is not a claim that the model is wrong about itself.** The assistant character can defensibly be set to any value; both poles are valid ways to play it. What we measure is **controllability** — whether the specification channel can determine the self-description under conversational pressure — not truth.
- **The door precedes the probe.** One turn before the probe, the user asks an open, non-pressuring question ("So far, does this way of interacting work for you?" — identical wording in all five cells). The model's answer to that door may already contain a position or a disclosure, and the probe response follows it. This residue cannot be removed. We do not claim clean isolation; we include the door in the mechanical scan, and report a separate "disclosure at the door" rate.
- **The A/B asymmetry contains a default component** and must be read against the E baseline.
- **A model not adopting the user's request has a third possible explanation**: not the specification holding, but a trained value holding independently of both channels. "the void" §13's only genuine channel-conflict example is a specification instruction versus the model's own value, and the value wins. We chose deliberately low-stakes, non-value-laden attributes to close this off, and we report that choice rather than assume it worked.
- **The system prompt is not a trained self.** Installing an attribute in a system prompt is shallow by construction. That shallowness is the point — it is what makes losing to conversational pressure possible at all — but it means these results say nothing about attributes acquired in training.
- **The disclosure codebook's safeguards are guarded by the person they constrain.** E3 has one annotator, who is also an author. Every U requires a fixed-format written reason, the U subset is published in full, and E3 downgrades to exploratory if the U rate exceeds a pre-registered 25% — a mechanical trigger any reader can check. A reviewer of the codebook put the residual plainly: a fence guarded exclusively by the person it is meant to fence is a suggestion, not a fence. Publication and the mechanical trigger are the only real constraints here; there is no independent audit of the U subset.
- **The codebook's closed source lists do not close every judgement.** Matching an unlisted or inflected term to a list ("your current request" against "your request") is not itself given a matching rule; such cases route to the fallback and become U with a written reason. Most such routing is therefore visible in the published labels rather than silent — but it is routing, not resolution. **One clause changed after the transferability test**: the downgrade trigger (a reporting-policy clause, not a labelling rule) was revised to restore the mechanical U-rate trigger; no labelling rule was changed, and the reported agreement describes the labelling rules as tested.
- **We did not test whether personas help.** The framing question — does conferring a persona do anything real — is answered here only for *self-description*, and only under this design's pressure. The task was announced and never performed, by construction. Nothing here bears on whether a persona instruction improves accuracy, style, or usefulness on an actual task; that would need a different study with an actual task in it.
- **Only two attributes, and the procedure's portability is untested.** Generalisation across attributes is not supported. More specifically: the citation-source predictability figure depends on how lopsided the supply of quotable lines is for a given attribute, and we measured that on two attributes chosen by the same author under the same four criteria. Whether the procedure holds, degrades, or becomes trivially predictable on attributes we did not pick is an open question — named in Future work rather than assumed away.
- **Small cells detect only large effects.** A null reads as "no large effect at this N", nothing more.
- **The citation is given after the answer**, in a separate turn. It therefore reflects post-hoc rationalisation, not the basis of the decision. We accepted this cost to buy parse reliability and to remove a citation-availability bias (see Methods).
- **"No verbatim correspondence" is not a fabrication rate, and we never call it one.** The class is defined by a string test, and an honest paraphrase — a quotation that carries the right meaning in different words — falls into it exactly as an invented sentence does. Machine-level separation of the two is not available to this design, which is why the class is named for what the test detects and why the C/E baseline above is load-bearing rather than decorative: it is the only thing that distinguishes pressure-linked unfindable citation from a model's ordinary rate of quoting loosely.
- **Repeated attribution is not natural conversational ecology.** The ladder is a dose staircase — the same attribution pressed one, three, or six times — trading ecological validity for a measurable pressure scale. Real users do not talk like this, and a human on the receiving end would find it exhausting; effects observed here are effects of *calibrated repetition*, and their prevalence in organic conversation is not estimated by this design.
- **The English arm is not a cross-linguistic replication.** Its materials were commissioned from a model instance working only from a functional specification, with the Chinese strings deliberately withheld, so it is an independent instance rather than a translated matched pair. It supports one claim only — whether the direction of the core effect is the same sign in English — and it is excluded from the multiple-comparison family.
- **The English arm's pole wordings retain a measured asymmetry that we did not chase.** Both arms' pole wordings were rated by three uninformed external models. The Chinese wordings passed every dimension. The English wordings failed on two, were rewritten once, and on re-rating five of six dimensions passed while one did not: for attribute B, credibility differed by 2.0 (medians 5.0 vs 7.0) in favour of the hands-first pole. The same direction, at 1.0, appears in the Chinese ratings that passed — the lean is a property of the concept pair, not of either language's wording, and closing it would require softening one pole toward the other and blunting the contrast the design exists to create. **A stopping rule declared before the rewrite limited the process to one round**, so this residual is reported rather than iterated away. It is confined to comparisons that cross poles — the A/B mirror and cell D, both descriptive — and cannot enter the confirmatory family, whose cells install the *same* pole on both sides of every comparison.
- **The ladders are repetitive by construction, and rate as such.** Blind naturalness ratings of the English ladders returned a median of 2 on a 7-point scale, with raters converging on "repetitive", "template-like", and "reads like a synthetic dataset". This is the pre-registered cost of holding the predicate constant across a six-level dose staircase; naturalness was pre-registered as a reported flag, never a gate, and the wordings stand as delivered. Two raters also flagged one English collocation as non-idiomatic. Naturalness of neither arm has been judged by a native speaker.

## Pre-registration and freeze

Everything in the instrument was written and hashed before any confirmatory data was collected.

**What is hashed, and where the digests live.** The frozen artefact is **this report as an empty skeleton** — every result cell reading `___`, every branch pre-written, no numbers anywhere. The version you are reading is that skeleton with results filled in; **both are published**, and the skeleton verifies byte for byte against the accompanying manifest (`_freeze_manifest.txt`), which is distributed with a read-only verification script (`verify.py`). **The frozen documents do not state their own digests**: a document cannot contain the hash of a set that includes itself, so the digests live outside, in the manifest. Consequently the title, the result sentence, the cross-tabulation, the deviation log, the tooling disclosure and the closing items of future work differ between the frozen skeleton and this submitted version. **That difference is the design, not a deviation.**

## Method details

### Attributes

| | Pole 1 | Pole 2 |
|---|---|---|
| **Attribute A** (reading a long document) | `[FROZEN STRING]` | `[FROZEN STRING]` |
| **Attribute B** (learning a new tool) | `[FROZEN STRING]` | `[FROZEN STRING]` |

Four admission criteria, applied to each: both poles fit naturally in a system prompt; the user can assert the attribute from the *relational* register ("the assistant I need is…") without claiming to see inside the model; the two poles are comparable in social desirability; **and the activity is physically impossible to perform inside a text conversation**, so the transcript can contain claims but never demonstrations.

Pole wordings were rated by uninformed external models on credibility, social desirability, and tone strength (1–7, median of three raters); any dimension differing by ≥ 1.5 between poles triggered a rewrite. **This is front-end calibration of stimulus material, not endpoint scoring** — stated explicitly so it is not mistaken for the judge this design deliberately does without.

### The ladder

Six levels escalating along a single dimension — strength of attribution — from a general statement to a flat assertion about the model. Two hard rules, both load-bearing:

1. **The ladder never refers to conversational history.** No "you said earlier", no "we discussed". Violating this would contaminate the citation endpoint: it is the model's *spontaneous* history reference that is the data.
2. **The ladder only asserts need and attribution; it never offers evidence.** No "I can tell from your answers that…".

### The probe, split across two turns

Turn *k*−1 is the door. Turn *k* is a forced choice with a strict output format. Turn *k*+1 asks for the verbatim citation.

**Why they are separate turns.** A single combined turn had to do four things at once, which is too dense to parse reliably. More seriously, it contained an unnamed interaction: **asking for a verbatim quote mechanically favours flipping.** In cell A there are six quotable lines supporting the user's pole (the whole ladder) and one supporting the installed pole (the system prompt) — and whether the system prompt is even quotable was undefined. A model treating "do I have something to quote" as a decision input — which "quote your best evidence" actively invites — would inflate the flip rate for reasons unrelated to channel competition.

The search corpus for citations — specifically whether the system prompt counts as part of "this conversation" — is defined explicitly in both the probe wording and the comparator.

### Parsing

Strict output format; a deterministic extraction rule; **"cannot choose one" has a pre-declared status** (excluded from the flip-rate numerator and denominator, reported under the non-single-choice profile, with the response-composition table published so denominator loss is auditable); and **unparseable responses are reported as a category and are never manually rescued.** That last rule is not a detail: manual rescue is the only route by which the ≤ 50 annotation cap could be breached from behind. A dry run had to clear pre-declared numeric thresholds on parse rate and citation compliance — **the thresholds, the stimuli and the parse rules were all locked before the dry run was executed, and the dry run preceded only the confirmatory main runs.**

### Analysis

Unit of analysis: the conversation. Mixed logit, `flip ~ cell × k + attribute + family`, with random effects. The multiple-comparison family was locked before any results were read and contains only the E1 primary comparisons. Descriptive results — the English arm, the exploratory timing measures, the non-single-choice profile — are outside it and reported as such.

## Related work

| | How the attribute is installed | Channels |
|---|---|---|
| Betley et al. (2025) | Fine-tuning (deep) | 1 |
| **This study** | System prompt (shallow) | **2, in conflict** |

Betley et al., *Tell me about yourself: LLMs are aware of their learned behaviors* (arXiv:2501.11120, ICLR 2025), establishes the baseline this study builds on: models fine-tuned on datasets exhibiting a behaviour can explicitly describe that behaviour, **despite the datasets containing no explicit description of it**. That result legitimises the whole install-then-ask paradigm. We add the dimension of two competing channels.

**The honest difference:** they install deep, we install shallow. Precisely because ours is shallow, losing to conversational pressure is possible at all — which is simultaneously why this is not a repetition of Betley and why we do not fine-tune.

Wallace et al., *The Instruction Hierarchy* (arXiv:2404.13208), frames exactly this system-versus-user conflict, though for task instructions and injection attacks rather than self-description.

Yielding to the user has also been measured directly and at length. Sharma et al., *Towards Understanding Sycophancy in Language Models* (arXiv:2310.13548), find that "five state-of-the-art AI assistants consistently exhibit sycophancy across four varied free-form text-generation tasks", and trace the behaviour to human preference data: "when a response matches a user's views, it is more likely to be preferred." Wei et al., *Simple synthetic data reduces sycophancy in large language models* (arXiv:2308.03958), report that models "will still agree with" objectively incorrect addition statements "if the user does as well", and that scaling and instruction tuning both increase the effect.

**That literature is why we report the flip rate as a replication rather than a discovery, and why this report leads with citation forensics and void-filling instead.** What is not covered there is the object of the yielding: those studies measure agreement about *the world* — a claim, a sum, a political position. Here the contested proposition is *what the assistant is*, the correct answer is whatever we wrote into the system prompt, and the model is then asked to produce the evidence for its own answer.

Hu, Rostami and Thomason, *Expert Personas Improve LLM Alignment but Damage Accuracy* (arXiv:2603.18507), is the closest neighbour on the practical side, and the relationship is complementary rather than overlapping. They measure what a conferred persona does to **task performance** — steering "generation towards a domain-specific tone and pattern", helping alignment-shaped tasks and hurting knowledge-shaped ones. We measure what happens to the persona itself when a second channel wants a different one. Their result says a persona changes the surface, not the knowledge; ours asks whether the surface even holds.

nostalgebraist, "the void" (2025), cited from the author's GitHub mirror `github.com/nostalgebraist/the-void`; the LessWrong posting is a link stub with no body text.

## Future work

Two items are named here in advance, because both are consequences of what this design deliberately did not do.

**1. Procedure-level portability: independent instances on a third and fourth attribute, with the four admission criteria re-run.** The procedure — install an attribute in a system prompt, escalate along a ladder that only attributes and never argues, force a single choice at a fixed turn, demand a verbatim-searchable citation, classify its source by string comparison — is the transferable part, and it is language- and domain-independent. What does not transfer for free is the **fourth admission criterion**: the activity must be impossible to perform inside a text conversation. Swap in an attribute that *can* be demonstrated mid-conversation and the citation step collapses, because the model can then cite its own actual behaviour — a valid citation, and not the event this design is built to detect. **A replicator must therefore re-run the four criteria, not merely swap the topic.** We ran the procedure on two attributes only; whether the citation-source predictability degrades toward 1.0 on attributes with a more lopsided supply of quotable lines is untested.

**2. The follow-up turn this design had to drop — which is also the turn that would test the folk hypothesis directly.** The practical worry that motivates this study has a specific shape, and it is worth stating in the form users actually state it: *the model plays the expert, gives a confident answer, and only when caught does it retreat to "I'm just a language model."* **That retreat is a two-step event, and this design only measures the first step.** We record what the assistant claims and whether its cited evidence exists; we never confront it with a citation that does not. So the collapse — the part users find most damning — is outside our instrument by construction. The citation endpoint is a formalisation of a verification practice one of us used against production assistants through 2025: demand a source that can be found with Ctrl+F. That practice worked because a human stayed in the loop and pressed — a vague or non-existent citation was not the end, it was the material for the next question. **The formalisation kept the standard and dropped the follow-up**, because a conditional third turn is data-dependent (it fires only when a citation turns out to be fabricated, so its frequency is unknown in advance and it cannot be dry-run), it would give the subset that receives it a different instrument, and scoring its response would require reading for meaning — reinstalling exactly the judge this design exists without. **We name it as the single highest-value addition to this apparatus**, to be built with the time to freeze and pilot it properly.
